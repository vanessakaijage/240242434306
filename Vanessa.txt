In these lectures, I learned that data mining is the process of discovering useful patterns and knowledge from large datasets, drawing on artificial intelligence, machine learning, statistics, and database systems, and that its key properties are automatic pattern discovery, prediction of likely outcomes, creation of actionable information, and a focus on very large datasets. I learned that it is the core step of the Knowledge Discovery in Databases (KDD) process, an iterative sequence of data cleaning, data integration, data selection, data transformation, data mining, pattern evaluation using interestingness measures (patterns that are useful, understandable, hypothesis-validating, and valid on new data), and finally knowledge presentation through visualization. I also learned that data mining uses techniques from several fields, including statistics (regression, cluster and correlation analysis, Bayesian networks), machine learning (such as decision trees), neural networks, database-oriented methods (frequent itemset scanning and attribute-oriented induction), and data visualization. In the next part, I learned that before mining data we must first understand and prepare it. Data is made up of objects, such as customers or students, described by attributes, which can be nominal (unordered categories like hair color), binary (two values like yes or no), ordinal (ordered values like small, medium, large), or numeric (interval-scaled with no true zero, or ratio-scaled with a true zero), and either discrete or continuous. To detect noise and outliers, we examine the center of the data (mean, median, mode), its spread, and the relationships between attributes, and visualization helps with this. The main focus was measuring how similar or different two objects are, which matters for clustering, outlier detection, and nearest-neighbor classification. Similarity ranges from 0 (completely different) to 1 (identical). For nominal data we count matching attributes, and for binary data we use a contingency table, applying the Jaccard coefficient when one state matters more and "both zero" matches should be ignored. For numeric data we use distance measures: Euclidean (straight-line), Manhattan (sum of differences along each attribute), Minkowski (a generalization of both), Supremum (the largest single difference), and weighted Euclidean (giving some attributes more importance). Ordinal data is converted to ranks scaled between 0 and 1 and then treated as numeric, while mixed-type data is handled by computing the difference for each attribute separately and combining them into one score. I also learned about cosine similarity, which compares documents by the angle between their word-count vectors, the Tanimoto coefficient as its version for binary data, and KL divergence, which measures how different two probability distributions are and is not symmetric. Finally, I learned that these measures can miss meaning, since "The cat bites a mouse" and "The mouse bites a cat" look similar to a computer but mean different things, and that more advanced methods like text embeddings and deep learning handle this better.
